How it works.
Three layers.

01InputTracker data
02EstimateCalculate
03ReduceActions
Layer 1 · Input & categorisation

Files in. Scopes out.

  • Tracker exports are read as they are
  • Each row is sorted into Scope 1, 2 or 3
  • Missing data is estimated, by rules or Gemini
  • Every estimate widens the range

Output: structured data tagged measured, estimated or illustrative

fleet.csvmeter.csvcloud.csv
S1S2S3
Layer 2 · Unified calculation

One formula per category.

  • Scope 1: litres × fuel factor
  • Scope 2: kWh × grid factor
  • Scope 3: activity × category factor
  • Uncertainty carried through: ±10% measured to ±50% missing

Output: a report with a range and a source on every number

58,100 kWh × 0.757 = 44.0 t
39.6 t ← ±10% → 48.4 t

Ranked by tonnes per rupee.

  • Each action: tonnes saved, cost and payback
  • Ranked by cost-efficiency
  • Stack actions into a scenario, with an overlap warning

Before and after.
What changes.

Before

  • Each team keeps its own spreadsheet, with no shared formula.
  • Scope 3 is a guess, and the report does not say so.
  • Grades compare absolute tonnes, so every large company fails.
  • The report is written by hand after the year has ended.

After

  • One place for each tracker, with the formula and source beside every figure.
  • Missing data is listed, filled with a labelled assumption, and widens the range.
  • Grades per employee, with the bands shown and the basis given.
  • A report that lists its sources, assumptions and sign-off, ready for review.

For TCS, the public data we can rebuild covers about 41% of the 9.15 lakh tonnes it discloses. The rest is listed as missing, not hidden.
